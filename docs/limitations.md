# Ограничения

Короткий честный список. Подробности — в `docs/model_card.md`, `docs/security.md`, `docs/norms.md`.

## Статус

- Исследовательский прототип, сделанный за время хакатона. Не медицинское изделие, не зарегистрирован.
- Не ставит диагноз и не назначает лечение. Решение принимает врач.
- Пороги и тексты отчётов не утверждены врачом. У порогов в `config/norms_ru.yaml` стоит статус проверки;
  он говорит только о том, сверено ли число с текстом источника. Спорные вопросы закрыты рабочими решениями
  капитана (`docs/review/medic_decisions.md`); врач команды подтверждает или правит их до предпитчинга.
- Проверки на пациентах не было.

## Данные

- **Учебный набор кейса (840 строк).** По нашим наблюдениям он похож на сконструированный: метка анемии
  совпадает с правилом ВОЗ в 840 строках из 840, а набор назначенных анализов подсказывает класс
  (модель, которая видит только «сдан / не сдан», даёт точность 0,254 при 0,137 у самого частого класса).
  Точность на этом наборе не равна клинической.
- **NHANES — данные США.** Распространённость дефицита железа, анализаторы и состав населения в России другие.
  На российских данных проверки не было.
- Экономический расчёт соединяет распространённость США и цены Москвы. Это иллюстрация.

## Где сдать рядом

- Список пунктов — только Москва и Московская область и только сети лабораторий, размеченные в OpenStreetMap
  на 04.10.2026: часть пунктов в OSM нет, у большинства нет адреса. Расстояние — по прямой, не по дорогам.
- Наличие конкретного анализа в пункте не проверяется: сети лабораторий обычно делают все анализы из «Что досдать»,
  кроме помеченных «в рознице недоступен».
- Подложке карты нужен интернет у пользователя; геолокация браузера работает только по HTTPS (или на 127.0.0.1).

## Модель уровня 2 (`case-v1`)

- Обучена и проверена на одном наборе в 840 строк (кросс-валидация). Внешней проверки нет.
- Режим бенчмарка (0,919 по 12 классам) пользуется подсказкой набора. Основной, клинический режим её
  не использует: 0,849 на полной строке.
- По одному общему анализу крови причина не определяется: 0,573 по 12 классам.
- Дефицит B6 и меди без их анализа не находится.
- Смешанный дефицит путается с железодефицитной и B12-дефицитной анемией.
- Свёртка 12 классов в 5 групп кейса — сопоставление команды (`config/class_mapping.yaml`);
  кейсодатель его не подтверждал.
- Если загрузить в сервис файл, на котором модель училась, метрики на экране завышены.
  Сервис ставит пометку и показывает числа кросс-валидации.

## Скрининг (`screen-v1`)

- Проверен на женщинах 18–49 лет: AUC 0,822 для ферритина ниже 15 мкг/л. Преимущество перед простым правилом
  по индексам небольшое: 7 процентных пунктов чувствительности (95 % ДИ от 0,6 до 13,9).
- У мужчин и женщин 50+ случаев мало (13 и 17 в тесте); преимущество перед правилом не показано.
- Завышает риск для порога 15 примерно на четверть: предсказано 0,098, наблюдается 0,077.
- При 30 % направленных не находится примерно каждый четвёртый случай (чувствительность 0,774),
  а подтверждается 18,5 % направлений.
- Нужен развёрнутый общий анализ крови с RDW, MCV и MCH. По одному гемоглобину оценка упрощённая (AUC 0,754).
- Справочник лаборатории по умолчанию — американский. Что стандартизация снимает сдвиг между анализаторами,
  проверено на одной смене анализатора внутри NHANES.

## Пороги и правила

- B12, активный B12 и гомоцистеин оцениваются по NICE NG239 — зарубежный источник, в КР РФ числового порога нет
  (решение капитана 04.10.2026, `medic_decisions.md`, п. 10; ожидает подтверждения врачом). Прочие зарубежные
  пороги не применяются (`policy.use_foreign: false`, разрешены поштучно `policy.foreign_allowed`).
- «Пограничный B12» — серая зона общего B12 180–350 пг/мл по NICE NG239. Флаг по неуверенности модели (полоса
  0,15–0,85) работает, только если число B12 выключено. ММК — без диагностического порога.
- «Норма» показателей — референс проекта по умолчанию (таблица 04.10.2026), а не референс конкретной лаборатории:
  у лаборатории с другим методом статусы могут отличаться. Локальные референсы можно передать в запросе или
  задать в конфигурации — тогда врачу показывается предупреждение. При беременности референсы проекта
  не применяются.
- B6, медь, ТТГ оцениваются по порогам с подписью «референс лаборатории». рСКФ 60 и 30 — стадии С3 и С4
  хронической болезни почек; по тексту КР РФ не сверено.
- Гемолиз — по сочетанию признаков (ответ врача 04.10.2026, `docs/review/medic_decisions.md`, п. 11): при анемии
  минимум два из четырёх — «подозрение», низкий гаптоглобин и ещё один — «сильное подозрение»; без анемии —
  «есть признаки, требующие проверки». Референсы по умолчанию — ЛДГ М 135–225, Ж 135–214 Ед/л, непрямой билирубин
  0–16,4 мкмоль/л, гаптоглобин 0,83–2,67 г/л (запасной, не универсальный норматив), ретикулоциты 0,68–1,86 %.
  Ретикулоциты — только в % (абсолютного числа в учебном наборе нет), при анемии с поправкой на гематокрит; RPI не
  считается. Церулоплазмин (М 0,15–0,30, Ж 0,16–0,45 г/л) значим только вместе со сниженной медью; возрастные
  референсы не заведены — только половые.
- Блок «срочно»: Hb ниже 80 г/л (беременные — ниже 70) — «тяжёлая анемия по ВОЗ»; лейкоциты ниже 2
  и тромбоциты ниже 50 — выбор проекта, без источника. Пациенту — «обратитесь к врачу сегодня»; вызов скорой
  сервис не советует.
- Анемия воспаления в пяти группах кейса — «неясного генеза» (`unexplained_anemia`); это сопоставление команды,
  вопрос наставнику кейса открыт. Скрытый дефицит отдельной группой не выделяется.
- Низкое НТЖ при нормальном ферритине — только «возможен функциональный дефицит железа»: НТЖ колеблется
  в течение дня, один результат не решает.
- Стадию дефицита железа сервис не определяет. Доз и схем лечения не приводит: «лечение — по клиническим
  рекомендациям Минздрава».
- Для части показателей порогов нет совсем (см. `docs/norms.md`, раздел о показателях без порога):
  для них выводится только «сдано / не сдано».
- Пороги ВОЗ для гемоглобина даны для 15–65 лет; для старших применяются по аналогии.
- При беременности работает только уровень 1. Ферритин не оценивается; модели, флаги и чек-лист выключены.
- Младше 18 лет ввод отклоняется.

## Ввод

- Фото бланка (JPEG, PNG, WEBP) и скан-PDF без текстового слоя распознаются локальным Tesseract только
  в Docker-версии; при запуске из исходников без `tesseract` — ошибка `ocr_unavailable`. PDF с текстом читается
  не больше 10 страниц, скан — не больше 5 страниц (200 dpi, все страницы вместе — не дольше 60 с).
  Есть форма, вставка текста, файл бланка (фото, PDF, TXT, CSV / XLSX одного анализа) и файл CSV / XLSX
  в схеме кейса.
- PDF любой лаборатории (поток П2): таблицы разбираются по словам заголовка («Тест / Исследование / Показатель»,
  «Результат / Значение», «Норма / Референсные значения», «Ед. изм. / Единицы») в любом порядке, без заголовка —
  по содержимому; строки вне таблиц — порядками «название значение единица норма» и «название значение норма
  единица». Проверено на реальном PDF ЕМИАС и на пяти придуманных бланках разных стилей
  (`tests/fixtures/pdf/`); на настоящих PDF Инвитро, Гемотеста, KDL, Хеликса, CMD не проверялось. Название
  сопоставляется со справочником только целиком (или по аббревиатуре в скобках): написание, которого нет
  в `config/analytes.yaml → aliases`, попадёт в «не распознано», а не будет угадано. Таблица, где одна
  ячейка разорвана на несколько строк без линий-разделителей, может разобраться хуже.
- Нормы с бланка (`reference_ranges`) берутся, только если единица распознана (или у показателя одна единица
  и она не указана); норма в неизвестной единице не пересчитывается и пропускается. Дата анализа — только
  с подписью «Дата взятия / выполнения / регистрации / выдачи» или «Дата:»; дата рождения не берётся никогда.
- Качество распознавания фото зависит от снимка: нужен хороший свет, без бликов и теней, бланк целиком
  и в фокусе. Проверено на придуманном печатном бланке (поворот по EXIF, шум, WEBP, 12 Мп); на реальных
  фото бланков разных лабораторий не проверялось. Рукописные бланки не поддерживаются. HEIC не принимается
  (на iPhone кнопка «Сфотографировать бланк» отдаёт JPEG).
- Пометка «проверьте значение» ставится, только если Tesseract не уверен в цифрах (conf < 80). Потерянная
  запятая читается уверенно («9,8» → «98» на сильно размытом снимке) — поэтому каждую строку с фото нужно
  сверить с бланком. Таблицы, где название и число стоят далеко или в разных колонках с переносами, могут
  разобраться хуже текста.
- Разбор бланка простой: значения нужно сверить глазами в таблице сверки до расчёта.
- В пакетной расшифровке файла значения ожидаются в основных единицах. Пересчёт есть только там, где единица
  столбца указана в сопоставлении (`mapping` у `/api/v1/benchmark`, шаг «Столбцы» на странице «Проверить на своём
  файле»); в командной строке (`deficitlens predict`) пересчёта нет.

## Сервис и безопасность

- Кабинет: логин и пароль, роли «пациент» и «врач», SQLite, журнал доступа врачей. Нет второго фактора,
  входа через ЕСИА (Госуслуги), восстановления пароля, резервных копий базы, разграничения по организациям.
- Кабинет — один экземпляр (SQLite в одном процессе); расчёты без входа масштабируются репликами.
- Шифрования канала (TLS) в самом сервисе нет: он работает по HTTP, TLS — на обратном прокси.
- Страница демо и маршруты `/ui/*` открыты без ключа; у них только лимит запросов на адрес.
- У `/api/v1/*` лимит на ключ есть только для тяжёлых запросов (batch, benchmark, columns, parse); `analyze`
  и `reference` без лимита. Ключ нельзя сменить без перезапуска.
- Лимиты и слоты тяжёлых расчётов считаются в памяти процесса — отдельно в каждой реплике.
- Вебхуков, очереди задач, обмена в формате FHIR нет.
- Данные реальных пациентов вводить нельзя: требования 152-ФЗ в прототипе не выполнены.

## Что не проверялось

- **Docker на amd64.** Образы собраны и проверены только на arm64 (Docker Desktop, macOS;). Предел памяти дочернего процесса PDF (`RLIMIT_AS`, Linux) в контейнере
  не проверялся.
- Работа в несколько реплик и нагрузка параллельными запросами.
- Установка пакета через `pip install -e .`.
- Запуск из исходников на Windows. Docker проверен на macOS (arm64).
