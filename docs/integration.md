# Интеграция: API Justmedit

Как подключить сервис к лабораторной или медицинской информационной системе. Готовые примеры —
в каталоге `examples/`. Точное описание маршрутов — `docs/CONTRACTS.md`, разделы «Контракт HTTP» и «Хранение
и кабинет». Машиночитаемое описание — `GET /api/v1/openapi.json` (OpenAPI 3.0, написано вручную, ключ не нужен;
тест `tests/api/test_openapi.py` сверяет его с маршрутами). Консоль запросов, примеры curl / JavaScript / Python
и справочник маршрутов — страница <http://127.0.0.1:8080/developers> (пункт «API» в шапке).

Примеры этого документа проверены на работающем сервисе. Загрузка бланка файлом проверена тестами и через страницу, мини-сайт клиники — в контейнере.

## Пять шагов подключения

1. **Запустить сервис** в своей сети: `docker compose up --build` из корня репозитория или без Docker
   (см. `README.md`). Порт по умолчанию — 8080, открыт только на `127.0.0.1`; другой адрес — `DL_PUBLISH`.
   Проверка: `curl http://127.0.0.1:8080/healthz`.
2. **Задать ключ API.** Переменная окружения `DL_API_KEYS` на стороне сервиса, ключи через запятую.
   На стороне клиента примеры читают ключ из переменной `DL_API_KEY`. Ключ передаётся заголовком `X-API-Key`
   и годится только для запросов с сервера. Из браузера и с чужого сайта — токен пользователя кабинета
   `Authorization: Bearer <токен>` (`POST /api/v1/auth/login`), домен сайта — в `DL_CORS_ORIGINS`.
3. **Сопоставить показатели.** Получить список кодов и единиц: `GET /api/v1/reference`. Коды совпадают
   с именами столбцов файла кейса: `hemoglobin`, `MCV`, `ferritin`, `vitamin_B12` и так далее.
4. **Отправить анализ.** Один — `POST /api/v1/analyze`. Много — `POST /api/v1/batch`.
   Передавать нужно только пол, возраст в годах и значения. Персональные данные не нужны.
5. **Разобрать ответ.** Главные поля: `level1.anemia`, `level2.case_group`, `hidden_deficiency`,
   `next_tests`, `reports.doctor`, `reports.patient`. Записи с ошибкой ввода приходят со статусом `rejected`
   и причиной.

Для скрининга по общему анализу крови стоит добавить шестой шаг: посчитать справочник своей лаборатории
(`deficitlens lab-reference`, см. ниже) и передавать его имя в поле `lab_reference`.

## Маршруты

| Маршрут | Ключ | Что делает |
|---|---|---|
| `GET /healthz` | нет | состояние и версии |
| `POST /api/v1/analyze` | да | один анализ → полный ответ |
| `POST /api/v1/batch` | да | пакет записей → сводка и результат по каждой |
| `POST /api/v1/columns` | да | файл CSV / XLSX → что сервис понял в каждом столбце, догадки для своих названий, «хватает ли данных» |
| `POST /api/v1/benchmark` | да | файл CSV / XLSX (схема кейса или своя структура с полем `mapping`) → предсказания, сводка, метрики при наличии меток |
| `POST /api/v1/parse` | да | бланк одного анализа (текст или файл: фото, PDF с текстом или скан, TXT, CSV / XLSX) → значения для сверки |
| `GET /api/v1/reference` | да | показатели, единицы, пороги с источниками, цены, версии |
| `GET /api/v1/openapi.json` | нет | описание API (OpenAPI 3.0) |
| `/api/v1/auth/*`, `/api/v1/me/*`, `/api/v1/shares/accept`, `/api/v1/doctor/*` | токен кабинета (Bearer) или cookie сайта | личный кабинет пациента и врача (ADR 0009), см. «Кабинет через API» |

«Ключ: да» — заголовок `X-API-Key` **или** `Authorization: Bearer <токен>` пользователя кабинета.
Маршруты `/ui/*` обслуживают страницу демо. Для интеграции они не предназначены: у них лимит запросов на адрес.

## Ключ и коды ответа

```bash
curl -X POST http://127.0.0.1:8080/api/v1/analyze \
  -H "X-API-Key: $DL_API_KEY" -H "Content-Type: application/json" \
  -d '{"sex": "F", "age_years": 34, "values": {"hemoglobin": 124}}'
```

| Код | Когда |
|---|---|
| 200 | запрос выполнен |
| 401 | нет заголовка `X-API-Key`; токен Bearer не найден или просрочен (`unauthorized`) |
| 403 | ключ не подходит |
| 413 | слишком большой запрос, файл или пакет |
| 422 | ошибка ввода |
| 429 | превышен лимит запросов: `/ui/*` — на адрес; тяжёлые `/api/v1/batch`, `columns`, `benchmark`, `parse` — на ключ (для токена — на пользователя) |
| 503 | заняты оба слота тяжёлых расчётов (`service_busy`); повторить через `Retry-After` секунд |
| 500 | внутренняя ошибка; тело — `{"error": {"code": "internal", "message": "Внутренняя ошибка"}}` |

Тело ошибки всегда одного вида:

```json
{"error": {"code": "missing_hemoglobin", "message": "Не указан гемоглобин: без него нельзя оценить анемию. Добавьте значение гемоглобина (г/л).", "field": "hemoglobin"}}
```

Сообщения написаны по-русски и говорят, что исправить. Значения анализов в сообщение не попадают.

## Один анализ: запрос

`POST /api/v1/analyze`, тело — JSON:

```json
{
  "sex": "F",
  "age_years": 34,
  "pregnancy": {"status": "no", "trimester": null},
  "values": {
    "hemoglobin": 124,
    "MCV": 82,
    "RDW": 15.2,
    "ferritin": {"value": 9, "unit": "ng/mL"}
  },
  "norms": "who",
  "mode": "clinical",
  "lab_reference": "default",
  "patient_ref": "row-17"
}
```

| Поле | Обязательное | Значения |
|---|---|---|
| `sex` | да | `F` или `M` |
| `age_years` | да | целое от 18 до 120. Сервис рассчитан на взрослых |
| `values` | да | словарь «код показателя → число» или «код → {`value`, `unit`}». Гемоглобин обязателен |
| `pregnancy` | нет | `status`: `no` (по умолчанию), `yes`, `unknown`; `trimester`: 1, 2, 3 |
| `norms` | нет | какой порог ферритина показывать первым: `who` (по умолчанию) или `ru` |
| `mode` | нет | `clinical` (по умолчанию), `benchmark`, `auto`. Для одного анализа `auto` означает `clinical` |
| `lab_reference` | нет | имя справочника ОАК лаборатории; по умолчанию `default`. Если в `config/norms_ru.yaml → local_references` есть набор с этим именем, его референсы заменяют референсы проекта по умолчанию |
| `reference_ranges` | нет | референсы лаборатории с бланка: «код → {`low`, `high`, `unit`}» (хотя бы одна граница; единица — любая допустимая для показателя). Заменяют референсы проекта по умолчанию для этих показателей |
| `patient_ref` | нет | произвольная метка строки; возвращается как есть. Не кладите сюда персональные данные |
| `provenance` | нет | произвольный словарь об источнике ввода |

Неизвестное поле — ошибка 422.

**Единицы.** Число без единицы считается записанным в канонической единице показателя: гемоглобин — г/л,
ферритин — мкг/л, B12 — пг/мл, фолаты — нг/мл, железо — мкмоль/л. Если единица другая, передайте её явно:
`{"value": 12.4, "unit": "g/dL"}`. Допустимые единицы каждого показателя — в `GET /api/v1/reference`,
поле `analytes[].units`. Каждый пересчёт попадает в ответ, в список `normalization`.

**Что не сдано.** Отсутствие ключа, `null` и пустая строка в клиническом режиме дают один и тот же ответ:
несданный анализ не несёт информации.

**Диапазоны.** Физически невозможное значение — ошибка 422. Нетипичное значение принимается, в ответе
появляется пометка. Жёсткие рамки ввода редактируются в `config/analytes.yaml → hard`.

**Референсы.** Статусы таблицы значений (`values[].norm`) считаются по диагностическим порогам и по референсу
проекта по умолчанию (`docs/norms.md`, раздел «Референсы проекта по умолчанию»). Если применён хотя бы один
референс лаборатории (`lab_reference` или `reference_ranges`), в ответе `references` = `{"set": "lab",
"local_analytes": [...], "warning": "Использованы референсные интервалы лаборатории. Они имеют приоритет над
значениями по умолчанию проекта; проверьте единицы, метод и возрастно-половую группу."}`, то же предупреждение — первой строкой в `limitations` и в разделе «Ограничения»
отчёта врачу. Ошибки референса (неизвестный показатель или единица, нижняя граница больше верхней) — 422 с полем
`reference_ranges.<код>`.

## Один анализ: ответ

Сокращённый пример для запроса выше без ферритина:

```json
{
  "version": {"engine": "0.1.0", "case_model": "case-v1", "screen_model": "screen-v1", "norms": "2026-10-04b"},
  "patient_ref": "row-17",
  "level1": {"anemia": false, "hemoglobin": 124.0, "threshold_g_l": 120.0, "severity": null, "urgent": [],
             "source": "ВОЗ, 2024: пороги гемоглобина для определения анемии"},
  "level2": {"enabled": true, "mode": "clinical", "completeness": "cbc", "case_group": "healthy",
             "anemia_class": "…", "deficiency_cause": "…", "confidence": "low",
             "probabilities": {"classes12": {}, "groups5": {}, "causes11": {}}, "plausible": []},
  "hidden_deficiency": {
    "applicable": true, "detected": true, "p_any": null, "rule_signals": [],
    "screening": {"applicable": true, "model": "screen-v1", "p_ferritin_lt15": 0.223, "p_ferritin_lt30": 0.452,
                  "risk": "high", "risk_ru": "высокий", "group": "F18-49", "validated_group": true,
                  "features": "hb_only", "lab_reference": "default", "recommend_ferritin": true},
    "summary_ru": "Гемоглобин в норме, но по общему анализу крови риск скрытого дефицита железа высокий: стоит досдать ферритин."
  },
  "flags": [],
  "checklist": [],
  "next_tests": [{"analyte": "ferritin", "name_ru": "Ферритин", "kind": "rule", "price_rub": 845, "reason": "…", "source": "…"}],
  "explanation": {"items_for": [], "items_against": [], "note": "…"},
  "values": [{"analyte": "hemoglobin", "value": 124.0, "unit": "г/л", "norm": {"status": "normal", "threshold_text": "…", "source": "…"}}],
  "reports": {"doctor": {"headline": "…", "sections": []}, "patient": {"headline": "…", "sections": []}},
  "normalization": [],
  "limitations": ["Исследовательский прототип, не медицинское изделие. Диагноз и лечение определяет врач."],
  "processing_ms": 12.8
}
```

В этом запросе общий анализ крови неполный (три показателя из девяти). Поэтому скрининг считает по упрощённой
модели: `"features": "hb_only"` — только гемоглобин, возраст и пол; MCV и RDW в неё не входят. Основная модель
(`"features": "full_cbc"`) включается, когда переданы все девять показателей ОАК: `hemoglobin`, `RBC`,
`hematocrit`, `MCV`, `MCH`, `MCHC`, `RDW`, `platelets`, `WBC`. Для примера 1 из `data/demo/examples.json`
с полным ОАК ответ — 0,449 и 0,675.

| Раздел ответа | Что в нём |
|---|---|
| `level1` | анемия по ВОЗ (да / нет), порог, тяжесть, блок «срочно». Модель этот вывод не меняет |
| `level2` | группа кейса (5 групп), класс (12), причина (11), вероятности, правдоподобные варианты, словесная уверенность. При беременности `enabled: false` |
| `hidden_deficiency` | только при нормальном гемоглобине: сигналы по порогам (`rule_signals`), оценка модели кейса (`p_any`, `by_nutrient`; по одному ОАК не выводится), скрининг по ОАК (`screening`) |
| `flags` | подсказки: ферритин под маской воспаления, нормальный MCV при высоком RDW, B12 требует подтверждения, микроцитоз не от железа, чек-лист исключений |
| `checklist` | при анемии без найденного дефицита: что исключено, что под подозрением, что не проверено |
| `next_tests` | что досдать: причина, цена в рублях, источник |
| `explanation` | какие сданные анализы поддерживают вывод, какие против |
| `values` | каждое значение со статусом, порогом и источником порога |
| `reports` | отчёт врачу и отчёт пациенту: заголовок и разделы со строками текста |
| `normalization` | пересчёты единиц и пометки о нетипичных значениях |
| `limitations` | ограничения, которые относятся к этому ответу |

Полная схема — `src/deficitlens_core/schemas.py`. Поля могут добавляться; существующие не меняются.

Вероятности в `level2` и `hidden_deficiency.p_any` получены на учебном наборе кейса. Вероятности
в `screening` — на данных США. Это оценки, а не измерения. Подробности — `docs/model_card.md`.

## Пакет записей

`POST /api/v1/batch`:

```json
{
  "with_reports": false,
  "records": [
    {"patient_ref": "row-1", "sex": "F", "age_years": 34, "values": {"hemoglobin": 124, "MCV": 82, "RDW": 15.2}},
    {"patient_ref": "row-2", "sex": "F", "age_years": 12, "values": {"hemoglobin": 118}}
  ]
}
```

Ответ:

```json
{
  "summary": {"total": 2, "done": 1, "rejected": 1, "processing_ms": 21.8},
  "items": [
    {"index": 0, "patient_ref": "row-1", "status": "done", "errors": [], "result": {"level1": {}, "level2": {}}},
    {"index": 1, "patient_ref": "row-2", "status": "rejected", "result": null,
     "errors": [{"code": "invalid_value", "message": "Возраст — целое число от 18 до 120 лет: сервис рассчитан на взрослых.", "field": "age_years"}]}
  ]
}
```

- Каждая запись — в том же формате, что и для `analyze`.
- Запись с ошибкой получает `rejected` и причину. Остальные считаются. Тихих поправок нет.
- `with_reports: false` убирает из результата тексты отчётов: ответ становится заметно короче.
- Предел — 10 000 записей (`DL_MAX_BATCH`) и 10 МБ тела (`DL_MAX_UPLOAD_MB`). Больше — 413.
- Записи считаются по одной, тем же движком, что и `analyze`. Скорость — в `docs/perf.md`.

Готовый сценарий для выгрузки ЛИС — `examples/lis_batch.py`.

## Файл в схеме кейса или своей структуры

`POST /api/v1/benchmark`, тело — `multipart/form-data`: поле `file` (CSV или XLSX), поле `mode`
(`auto`, `clinical`, `benchmark`) и необязательное поле `mapping` — JSON
`{"столбец файла": "код" | {"code": "код", "unit": "единица"} | "ignore"}` (ошибка — 422 `invalid_mapping`).
Чтобы составить `mapping`, сначала отправьте тот же файл в `POST /api/v1/columns`: ответ покажет, что сервис понял
в каждом столбце, догадки для своих названий («HGB, г/дл») и чего не хватает для анализа (`requirements`).
Готовый запасной файл для проверки — `data/demo/example_case.csv` (три придуманные строки).

```bash
curl -X POST http://127.0.0.1:8080/api/v1/benchmark \
  -H "X-API-Key: $DL_API_KEY" -F "file=@my_file.csv" -F "mode=auto"

# тот же запрос, ответ — готовый CSV
curl -X POST "http://127.0.0.1:8080/api/v1/benchmark?format=csv" \
  -H "X-API-Key: $DL_API_KEY" -F "file=@my_file.csv" -o pred.csv
```

Формат файла: строка на пациента; столбцы — `sex`, `age_years` и коды показателей. Необязательные столбцы:
`patient_id` и метки `anemia`, `anemia_class`, `deficiency_cause` (или `anemia_cause`). Неизвестные столбцы
игнорируются и перечисляются в сводке. Значения — в канонических единицах; другая единица пересчитывается,
только если она указана для столбца в `mapping` (`{"code": "hemoglobin", "unit": "g/dL"}`).

Ответ в формате JSON:

| Поле | Что в нём |
|---|---|
| `summary` | сколько строк принято и отклонено и почему; распознанные столбцы; выбранный режим и причина выбора; время; при наличии меток — метрики обоих режимов |
| `preview` | первые 20 строк результата |
| `csv` | весь результат текстом CSV |
| `cv_metrics` | появляется, если файл побайтно совпал с набором, на котором обучена модель: числа кросс-валидации |

Столбцы результата: `patient_id`, `anemia`, `case_group`, `anemia_class`, `deficiency_cause`, `confidence`,
`hidden_deficiency`, `mode`, `status`, `reject_reason`.

Если загрузить файл, на котором модель училась, метрики в `summary.metrics` будут завышены. Сервис ставит
признак `same_as_training_data` и пишет об этом в `summary.notes`.

## Текст бланка

`POST /api/v1/parse`, тело `{"text": "Гемоглобин 124 г/л\nФерритин: 9,0 мкг/л"}` или `multipart/form-data`
с полем `file`: фото бланка (JPEG, PNG, WEBP), PDF любой лаборатории с текстом (до 10 страниц) или скан
(до 5 страниц), TXT, CSV / XLSX одного анализа (коды показателей в заголовке или столбцы «название, число,
единица»). Фото и скан распознаёт локальный Tesseract — он есть в Docker-версии; без него — 422 `ocr_unavailable`.

```bash
curl -X POST http://127.0.0.1:8080/api/v1/parse -H "X-API-Key: $DL_API_KEY" -F "file=@blank.pdf"
```

Ответ: `{"values": {…}, "unrecognized": […], "notes": […], "reference_ranges": {…}, "ignored": […], "date": …}`,
для файла ещё `source`; для фото и скана — `warnings` («строка 6: Ферритин — проверьте значение») и `check`
(коды показателей, где распознавание не уверено). `reference_ranges` — нормы с бланка, `date` — дата анализа
с бланка. В `unrecognized` — только номер строки и причина («строка 9: название показателя не распознано»),
без текста бланка. Расшифровку маршрут не делает: значения нужно показать человеку для сверки и затем отправить
в `analyze` (нормы с бланка — в поле `reference_ranges`).
Ошибки файла — 422 с кодом `bad_pdf`, `pdf_too_complex`, `no_text_layer` (в PDF нет ни текста, ни картинок),
`bad_image`, `heic_unsupported`, `image_too_large`, `ocr_unavailable`, `ocr_failed`, `too_many_columns`,
`too_many_rows` или `file_too_large`.

## Справочник

`GET /api/v1/reference` возвращает: `analytes` (код, название, единица, допустимые единицы, цена),
`thresholds` (пороги с источником, статусом проверки и признаком «применяется»), `prices`, `sources`,
`policy` (правило источников), `versions`.

## Справочник своей лаборатории для скрининга

Модель скрининга стандартизует общий анализ крови по медиане и квартилям лаборатории. Справочник
по умолчанию построен по NHANES. Свой справочник считается по выгрузке ОАК; ферритин и диагнозы не нужны:

```bash
PYTHONPATH=src python3 -m deficitlens_core.cli lab-reference --in cbc_export.csv --name my_lab
```

Команда дописывает справочник в `config/lab_reference.yaml`. После перезапуска сервиса имя `my_lab`
можно передавать в поле `lab_reference`. Ключ `--dry-run` покажет справочник, не записывая файл.
Если указанного имени нет, используется `default`.

## Кабинет через API

Личный кабинет (ADR 0009) доступен тем же API: свой сайт клиники может хранить анализы пациента у нас
и показывать историю. Без входа ничего не хранится; в кабинете значения зашифрованы (`docs/security.md`,
«Личный кабинет»). Это демо: реальные данные в кабинет не вводить.

- Вход: `POST /api/v1/auth/register` (`{"login","password","role":"patient"|"doctor","consent":true}`) или
  `POST /api/v1/auth/login` → в ответе `token`. Дальше — заголовок `Authorization: Bearer <токен>`.
  Токен входа живёт 7 дней; именованный токен для интеграции — 30 дней (`POST /api/v1/me/tokens`, по Bearer —
  с паролем в поле `password`).
- Пациент: записи анализов `/api/v1/me/records` (`POST` → 201 и ответ движка), история
  `GET /api/v1/me/history`, выгрузка `GET /api/v1/me/export?format=json|csv`, загрузка `POST /api/v1/me/import`,
  доступ врачу `POST /api/v1/me/shares` (`{"days": 1|7|30|90}`) и журнал доступа `GET /api/v1/me/access-log`,
  удаление аккаунта `DELETE /api/v1/me` с паролем.
- Врач: принять ссылку `POST /api/v1/shares/accept`, пациенты и их история `/api/v1/doctor/patients/*`,
  референсы своей лаборатории `/api/v1/doctor/lab-refs` (подставляются в его расчёты).
- Тела запросов — только JSON с `Content-Type: application/json` (иначе 415). Из браузера с чужого сайта —
  только Bearer и домен в `DL_CORS_ORIGINS` (CORS без cookie).

Пример по шагам — README, «Личный кабинет»; все маршруты и формы ответов — `docs/CONTRACTS.md`, «Хранение
и кабинет»; консоль с готовым сценарием — `/developers`.

## Чего в API нет

- Асинхронных задач и очереди: ответ приходит в том же запросе.
- Обратных вызовов (вебхуков).
- Обмена в формате FHIR и СЭМД.
- Встроенного Swagger UI: есть `GET /api/v1/openapi.json` и своя страница `/developers`.
- Лимита запросов и квот для лёгких маршрутов `/api/v1/analyze` и `/api/v1/reference`. У тяжёлых
  (batch, benchmark, columns, parse) — не больше `DL_UI_RATE_PER_MIN` запросов в минуту на ключ (429);
  у них и у истории и загрузки кабинета (`me/history`, история пациента у врача, `me/import`) — не больше двух
  расчётов одновременно на процесс (503 `service_busy` с `Retry-After`).
- Отдельных ключей с разными правами.
- Хранения результатов по ключу API: ответ `analyze` с ключом не сохраняется. Хранить анализы и получать
  их позже можно только в личном кабинете (Bearer-токен пользователя).
