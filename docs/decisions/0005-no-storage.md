# ADR 0005. Без хранения

> Частично заменён ADR 0009 (04.10.2026, вечер): без входа — как здесь; в личном кабинете данные хранятся.

Принято 04.10.2026 (волна 3 прежней версии, тег `prepitch`; действует с волны 0 — ADR 0001). Переписано 04.10.2026 (волна 4) под базовый вариант (ADR 0006).

## Контекст

Сервис получает результаты анализов — медицинские данные. Хранение потребовало бы БД, изоляции клиник, аудита,
удаления по запросу, бэкапов и выполнения 152-ФЗ — это не помещается в хакатон (ADR 0001). При этом кейс требует
«безопасность ПДн» и «масштабируемость», а п. 8.3 Положения — показать обработку данных.

## Решение

Как это сделано в базовом варианте (`src/deficitlens_api/security.py`, `service.py`, `settings.py`;
`docs/security.md`):

- Базы данных, сессий и очередей нет: результат возвращается в том же ответе.
- Тело запроса читается потоком в память с пределом `DL_MAX_UPLOAD_MB` (по умолчанию 10 МБ): больше — 413.
- Файл, загруженный в `/api/v1/benchmark` или на страницу «Проверить на своём файле», на время разбора
  записывается во временный каталог и удаляется в `finally`, в том числе при ошибке. В контейнере `/tmp` — `tmpfs`.
  В прежней версии файл на диск не попадал вовсе; это отличие базового варианта зафиксировано здесь.
  **Устарело:** файл разбирается в памяти и на диск не пишется (`service.py`, `docs/security.md`, «Что сервис
  не хранит»).
- В журнале — время, метод, путь (до 200 символов), код, длительность; тела запросов, строка запроса и значения
  анализов не пишутся. `deficitlens serve` запускает uvicorn с `log_level="warning"`.
- Ответы `/api/`, `/ui/`, `/healthz` — с `Cache-Control: no-store`. Страница ничего не хранит в браузере:
  ни `localStorage`, ни `sessionStorage`, ни cookies (`static/app.js`).
  **Устарело в части cookie:** cookie сессии (`jm_session`, HttpOnly, ставит сервер) — только в кабинете
  (ADR 0009); без входа cookie нет, `localStorage` и `sessionStorage` не используются.
- Демо не принимает ПДн: плашка «Демо. Не вводите персональные данные. Не медицинское изделие.» на всех страницах;
  лишнее поле в запросе — 422; `patient_ref` возвращается как есть и не сохраняется.

## Статус

Принято. Реализовано в базовом варианте с одним отличием от прежней версии (временный файл при разборе таблицы;
позже убран — файл разбирается в памяти). Для работы без входа действует; кабинет с хранением — ADR 0009.
Усиление по ревизиям прежней версии (путь в журнале через `repr`, проверка распакованного XLSX, слоты тяжёлых
расчётов) переносится в этапе 4а.

## Последствия

- Нечего изолировать, удалять и бэкапить; масштабирование — репликами контейнера без состояния
  (`docs/architecture.md`, «Как масштабируется»). После ADR 0009 это верно для расчётов без входа; кабинет —
  один экземпляр с базой SQLite.
- Проверяемо тестом: «канарейка» в журнале (`tests/api/test_api.py`, `test_log_has_no_values`).
- Нельзя «получить результат позже», нет истории пациента, нет асинхронных пакетов: пакет — синхронный ответ,
  до `DL_MAX_BATCH` записей (по умолчанию 10 000; в прежней версии — 5 000).
- Лимит `/ui/*` живёт в памяти процесса и не делится между репликами.
- Строка бланка с нераспознанным показателем возвращается пользователю (до 60 символов); если в ней были ПДн,
  они вернутся тому же пользователю, но не сохранятся (`docs/security.md`). Сборку фрагмента из распознанных
  частей переносит этап 4а.

## Отвергнутые варианты

- **SQLite или файл с результатами для демо** — ПДн на диске и обязанности по 152-ФЗ без пользы для сценария.
- **Логи запросов для отладки** — значения анализов в журнале; вместо этого — журнал без данных и тест-«канарейка».
- **Фоновый worker с очередью для пакетов** — нужны очередь и хранение результатов; векторный пакет укладывается
  в один запрос (10 000 строк клинического режима — 0,72 с, `docs/perf.md`).
