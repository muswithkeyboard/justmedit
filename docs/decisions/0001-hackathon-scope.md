# ADR 0001. Хакатонная версия: что вырезано из плана v3.2 и почему

Принято 04.10.2026 (волна 0 прежней версии, тег `prepitch`). Переписано 04.10.2026 (волна 4) под базовый вариант
(ADR 0006): что совпадает — оставлено, что в базовом варианте иначе — исправлено и помечено «в базовом варианте».

> Уточнено ADR 0009 (04.10.2026, вечер): личный кабинет с хранением добавлен; без входа — по-прежнему без хранения.

## Контекст

До сдачи (5 октября, 14:00) меньше 37 часов, кода на старте не было. План v3.2 описывает промышленный сервис:
БД с изоляцией клиник, кабинеты, встраивание, эксплуатацию. Целиком он не помещается. Жюри оценивает шесть равных
критериев, и техническая реализуемость снижается, если решение не запускается (п. 7.8 Положения;
`docs/HACKATHON_RULES.md`).

## Решение

Строим один сценарий, доведённый до конца: «ввёл или загрузил анализ → уровень 1 по ВОЗ, группа и причина,
скрытые дефициты, следующий анализ с ценой → отчёт врачу и пациенту». Сдаём модель (`deficitlens_core`), демо
и пример интеграции (API с ключом).

Не строим: БД, RLS, роли Postgres, кабинеты и вход, гранты, виджет, вебхуки, worker,
аудит, удаление, бэкапы, FHIR, OCR фото, tesseract, мультиклиничность, nginx/TLS, песочницу.

Оставлено как P0, хотя в v3.2 было частью больших этапов: авторизация по ключу API (п. 8.3 Положения требует
показать «авторизацию»), лимит запросов, заголовки безопасности.

Как это выглядит в базовом варианте:

- Демо — две страницы: главная `/` и «Проверить на своём файле» `/benchmark` (`src/deficitlens_api/app.py`).
  На главной — блок «Проверка API» (шаг 6 демо, правка 10; `docs/demo_script.md`; сейчас — свёрнутый блок
  «Для проверяющих: проверка API»).
- API: `/api/v1/analyze`, `/batch`, `/benchmark`, `/parse`, `/reference` под ключом `X-API-Key`
  (сравнение через `hmac.compare_digest`); `/ui/*` — без ключа, с лимитом 30 запросов в минуту на адрес
  (`src/deficitlens_api/security.py`, `settings.py`). Порт 8080 везде (правка 11).
- Конфигурация — только в `config/`. Параметры режима `auto` лежат в `config/class_mapping.yaml` (`auto_mode`);
  отдельного `config/engine.yaml`, как в прежней версии, нет.
- Python: `requires-python = ">=3.12"`; модели обучены на Python 3.13.16 и scikit-learn 1.9.1
  (`models/*/metadata.json`); scikit-learn закреплён `==1.9.1` (`pyproject.toml`).
- Фильтр текста пациенту (`config/forbidden_patient_words.yaml`): совпадение по подстроке без учёта регистра;
  строка с запрещённой подстрокой целиком заменяется нейтральной «Обсудите этот результат с врачом.»
  (в прежней версии — проверка по началу слова).

## Статус

Принято. Действует в базовом варианте. Долг: `docs/roadmap.md` («спроектировано, не реализовано») в базовом
варианте отсутствовал; позже он добавлен.

## Последствия

- Демо и API работают без БД и без хранения (ADR 0005); масштабирование — репликами контейнера без состояния
  (`docs/architecture.md`).
- Без `docs/roadmap.md` жюри не видит пути к промышленной версии одной страницей — его нужно написать
  (предложение подготовлено на этапе 4в).
- Разбор PDF, Docker-профили `verify`/`cli`/`clinic` и мини-сайт клиники переносятся из прежней версии в волне 4
  (этапы 4а и 4б).

## Отвергнутые варианты

- **План v3.2 целиком** — не помещается в 37 часов; незапускаемое решение теряет баллы по п. 7.8.
- **Без авторизации, «только демо»** — п. 8.3 Положения прямо называет авторизацию среди элементов, которые
  нужно показать.
- **Кабинеты с входом вместо ключа API** — требуют хранения учётных записей (ADR 0005).
