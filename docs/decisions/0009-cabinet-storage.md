# ADR 0009. Личный кабинет пациента и врача; хранение данных на сервере

Дата: 04.10.2026 (вечер). Частично заменяет ADR 0005 «Без хранения».

## Контекст

Решение пользователя 04.10.2026: пациент регистрируется (логин и пароль), сохраняет анализы, видит историю и её
анализ, выгружает и загружает данные, может запросить полное удаление; делится доступом с врачом по ссылке на
выбранный срок и отзывает его. Врач указывает клинику, хранит референсы своей лаборатории, видит историю пациентов,
открывших ему доступ. Всё это — с хранением на сервере. Нужен и API для встраивания (кабинет через API).

ADR 0005 («сервис ничего не хранит») сохраняется для работы **без входа**.

## Решение

- Два режима. Без входа — как раньше: ничего не хранится (ADR 0005). В кабинете — хранение с согласием при
  регистрации, до удаления пользователем.
- Хранилище — SQLite (`DL_DATA_DIR`, в Docker — том `jm-data`, остальная ФС контейнера только для чтения),
  `secure_delete`, WAL. Значения анализов, сводки и референсы — зашифрованы (Fernet, `DL_DATA_KEY`; без ключа он
  создаётся файлом рядом с базой — только для демо). Логин, роль, клиника, даты и сроки связей — открытым текстом
  (нужны для поиска).
- Пароли — scrypt с солью; одинаковый ответ на неверный логин и пароль; лимит попыток.
- Сессии сайта — cookie HttpOnly, SameSite=Strict; изменяющие запросы — с заголовком `X-Justmedit: 1` и своим
  Origin (CSRF). Внешние сайты — Bearer-токен, CORS по списку `DL_CORS_ORIGINS`. В базе — только хэши токенов.
- Полное удаление (`DELETE /api/v1/me` с паролем) стирает пользователя, записи, ссылки, референсы, журнал доступа
  в одной транзакции, затем `VACUUM`.
- Доступ врача — только врачу с аккаунтом, по одноразовой ссылке (`/share#токен`: фрагмент не уходит на сервер и в
  журнал), на 1/7/30/90 дней; пациент отзывает в любой момент; каждое открытие истории врачом пишется в журнал,
  который видит пациент.
- Журнал сервера по-прежнему без значений, логинов и токенов: метод, путь, код, время.

## Рассмотрено и отвергнуто

- Хранение в браузере (localStorage) — не переносится между устройствами, врач не увидит историю.
- PostgreSQL — лишний сервис для демо; SQLite в одном процессе достаточно (масштабирование — `docs/roadmap.md`).
- Вход через Госуслуги / ЕСИА — недоступно на хакатоне.

## Последствия

- Сообщение «ничего не хранит» уточнено: «без входа — ничего; в кабинете — шифрованно, по согласию, с удалением».
- Это прототип, не система, соответствующая 152-ФЗ: нет формального согласия на обработку специальных категорий
  ПДн, резервных копий, разграничения по организациям, аттестации. Плашка «Демо. Не вводите персональные данные»
  остаётся; в кабинет не вводить реальные данные.

## Уточнения после ревизии безопасности (04.10.2026, вечер)

- Полного `VACUUM` при удалении аккаунта нет: он держал общий замок, пока переписывалась вся база. Удалённое
  затирает `secure_delete`, свободные страницы отдаются порциями `incremental_vacuum`, после каждого удаления —
  `wal_checkpoint(TRUNCATE)`.
- Пределы: запись ≤ 16 КБ, данные пользователя ≤ 5 МБ, база ≤ `DL_DATA_MAX_MB`, регистрации — 10 в час с адреса
  и `DL_MAX_SIGNUPS_PER_DAY` в сутки.
- Токен API (Bearer) без пароля не создаёт токенов и ссылок врачу; токен входа живёт вместе с cookie (7 дней);
  есть «выйти везде» и смена пароля. Заголовки прокси — только от `DL_TRUSTED_PROXIES`. Ключ — `DL_DATA_KEY` или
  `DL_DATA_KEY_FILE`, вне демо — не в томе с базой. Подробно — `docs/security.md`, «Личный кабинет».
