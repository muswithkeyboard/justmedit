# Justmedit

Сервис расшифровки анализов крови на анемию и скрытые дефициты.

Веб-сервис, который по общему анализу крови и другим лабораторным показателям определяет анемию по правилу ВОЗ,
оценивает её группу и причину, ищет скрытые дефициты при нормальном гемоглобине и подсказывает, какой анализ досдать.

Решение кейса Сеченовского университета на хакатоне MedITron 2026.
**Исследовательский прототип. Не медицинское изделие. Решение принимает врач.**

## Цели и задачи

Цель — помочь врачу и лаборатории не пропустить дефицит железа, B12 и фолатов, в том числе когда гемоглобин ещё в норме.

Задачи из условия кейса:

1. Уровень 1: есть анемия или нет.
2. Уровень 2: группа анемии (5 групп), класс (12) и причина дефицита.
3. Скрытый дефицит при нормальном гемоглобине.
4. Трудные случаи: ферритин при воспалении, нормальный MCV при двух дефицитах, пограничный B12,
   микроцитоз не от железа, анемия без найденного дефицита.
5. Два отчёта: врачу и пациенту. Рекомендации по дообследованию.
6. Ввод из формы и из файла; API для подключения к системе клиники или лаборатории.

## Что реализовано

- **Уровень 1** — правило ВОЗ 2024 по гемоглобину и полу, пороги для беременных по триместрам, тяжесть, блок «срочно»
  (Hb ниже 80 г/л, у беременных ниже 70 — «тяжёлая анемия по ВОЗ»; лейкоциты ниже 2 и тромбоциты ниже 50 — «выбор
  проекта»; пациенту — «обратитесь к врачу сегодня»). Модель этот вывод не меняет.
- **Уровень 2** — модель `case-v1`: 14 профилей → 12 классов → причина → 5 групп. Два режима:
  клинический (основной; несданный анализ не несёт информации) и режим бенчмарка (для файлов в схеме кейса).
- **Правила-маски** — флаги с источником для пяти трудных случаев и чек-лист исключений
  («Дефицит по сданным анализам не найден — чек-лист исключений»). При воспалении без дефицита нутриентов врачу
  показывается класс «анемия воспаления»; если при этом есть признаки дефицита железа — строка «возможна
  железодефицитная анемия на фоне воспаления». Низкое НТЖ при нормальном ферритине — «возможен функциональный
  дефицит железа». Рабочие решения по вопросам врачу — `docs/review/medic_decisions.md`.
- **Скрытый дефицит** — три источника: пороги по сданным анализам, модель кейса, скрининг `screen-v1`
  по одному общему анализу крови (обучен и проверен на открытых данных NHANES, США).
- **Следующий анализ** — что досдать и почему; **где сдать рядом**: 5 ближайших пунктов сетей лабораторий Москвы
  и области по положению или по точке на карте (список из OpenStreetMap лежит в репозитории, ближайшие считаются
  в браузере, координаты никуда не уходят), ссылки на поиск в Яндекс Картах и **средняя цена анализов в выбранном
  регионе** (регион — по точке или из списка; цены есть для Москвы и области) (ADR 0008).
- **Выгрузка отчёта** — DOCX (собирается в браузере) и PDF (окно печати → «Сохранить как PDF»), для открытой
  вкладки «Врачу» или «Пациенту».
- **Отчёты** — врачу и пациенту. Пациенту — без диагнозов, лекарств и доз.
- **Ввод** — форма; бланк одного анализа текстом или файлом (фото бланка JPEG / PNG / WEBP; PDF любой
  лаборатории — с текстом или скан; TXT, CSV / XLSX; фото и скан распознаёт локальный Tesseract — OCR
  в Docker-версии) с таблицей сверки перед расчётом: значения с фото и скана, где распознавание не уверено,
  помечены «проверьте значение»; файл CSV или XLSX для пакетной расшифровки —
  в схеме кейса или в своей структуре: сервис сопоставляет столбцы (свои названия вроде «HGB, г/дл» —
  догадкой, её можно поправить), пересчитывает выбранные единицы и предупреждает, чего не хватает для анализа
  (`/ui/columns`, поле `mapping`). На телефоне — кнопка «Сфотографировать бланк».
- **API с ключом**, страница демо, командная строка, тесты, примеры интеграции: curl, клиент на Python, пакет
  из выгрузки ЛИС и мини-сайт клиники (`examples/clinic_site`: ключ API только на сервере клиники, пациенту —
  только его отчёт).
- **Docker** — сервис, проверка в контейнере, командная строка и мини-сайт клиники в одном `docker-compose.yml`.
- **Личный кабинет** (ADR 0009, API — `/api/v1/auth/*`, `/api/v1/me/*`, `/api/v1/doctor/*`): пациент и врач
  с логином и паролем; пациент хранит анализы, видит историю и её анализ, выгружает (JSON, CSV в схеме кейса)
  и загружает данные, удаляет аккаунт целиком; открывает врачу доступ по одноразовой ссылке на 1, 7, 30 или 90 дней
  и отзывает его, видит журнал доступа. Врач хранит референсы своей лаборатории (JSON или CSV / XLSX) — они
  подставляются в его расчёты. Без входа сервис по-прежнему ничего не хранит; в кабинете значения анализов
  в базе зашифрованы (`docs/security.md`, «Личный кабинет»). Это демо: реальные данные в кабинет не вводить.

Чего нет: входа через Госуслуги (ЕСИА), второго фактора, резервных копий кабинета, распознавания рукописных
бланков, обмена в формате FHIR.
Полный список — `docs/limitations.md`.

## Развёртывание, запуск и использование

### Быстрый старт (Docker)

Нужны Docker и Docker Compose v2. Рабочий каталог — корень репозитория (там лежит `docker-compose.yml`).

```bash
docker compose up --build
```

Страница демо: <http://127.0.0.1:8080/>. Проверка: `curl http://127.0.0.1:8080/healthz`.
Ключ API по умолчанию — демо-ключ `dl-demo-key` (см. [Ключ API](#ключ-api)).

Проверено на macOS arm64 (Docker 29.7.2, Compose v5.3.1): с чистого клона образ собирается примерно за минуту,
сервис здоров через несколько секунд после запуска. Последний прогон (05.10.2026): в контейнере с файлами данных —
511 тестов PASS, без них — 495 PASS и 16 SKIP (тестам нужны данные). На amd64 образ не собирался.

Другие команды Docker (рабочий каталог тот же):

| Команда | Что делает |
|---|---|
| `docker compose run --rm verify` | тесты и проверка сервиса в контейнере, таблица PASS / FAIL / SKIP. Без файлов данных в `data/case`, `data/nhanes` проверки с данными получают SKIP (проверено: PASS 17, SKIP 2, FAIL 0); с данными — PASS 18 |
| `docker compose run --rm cli predict --in /data/in/x.csv --out /data/out/pred.csv` | пакетная расшифровка: файл кладётся в `./data/in`, результат появляется в `./data/out`. На Linux удобнее `make docker-predict IN=x.csv OUT=pred.csv` — файл результата будет принадлежать вам |
| `docker compose --profile clinic up --build` | сервис и мини-сайт клиники на <http://127.0.0.1:8081> |
| `docker compose --profile tools --profile clinic down` | остановить всё (то же — `make docker-down`) |

Порты по умолчанию открыты только на этой машине (`127.0.0.1`). Адрес и порт сервиса задаёт `DL_PUBLISH`
(по умолчанию `127.0.0.1:8080`), мини-сайта — `DL_CLINIC_PUBLISH` (`127.0.0.1:8081`).

### Запуск без Docker

Нужен Python 3.12 или 3.13 (модели обучены на 3.13.16). Рабочий каталог — корень репозитория.

```bash
uv sync --extra dev        # или: pip install -r requirements.txt
PYTHONPATH=src DL_API_KEYS=dl-demo-key uv run python -m uvicorn deficitlens_api.app:app --host 127.0.0.1 --port 8080 --no-access-log --no-proxy-headers
```

Распознавание фото и сканов PDF без Docker требует установленного Tesseract с языком `rus`
(`brew install tesseract tesseract-lang`, `apt install tesseract-ocr tesseract-ocr-rus`); без него остальное работает.
Демо-аккаунты кабинета (пациент с тремя анализами и врач с доступом к нему) создаёт `python3 scripts/seed_demo.py`
при запущенном сервисе — локальном или в Docker (адрес — `--base`, по умолчанию `http://127.0.0.1:8080`; пароль —
`--password`, без него случайный и печатается).

То же одной командой: `make run`. Мини-сайт клиники без Docker: `make clinic` во втором терминале
(нужен запущенный `make run`).

Файлы моделей `models/*/*.joblib` привязаны к версии scikit-learn (1.9.1, она закреплена в `requirements.txt`).
При другой версии scikit-learn модели нужно переобучить: `deficitlens train` (нужны файлы данных, см. [Данные](#данные)).

### Ключ API

- Маршруты `/api/v1/*` требуют заголовок `X-API-Key`. Без ключа — 401, с неверным — 403.
- Ключи задаются переменной окружения `DL_API_KEYS`, через запятую.
- В `docker-compose.yml` по умолчанию стоит демо-ключ `dl-demo-key`. Он известен всем, кто видел репозиторий.
  Свой ключ: `DL_API_KEYS=<ключ> docker compose up`.
- Если `DL_API_KEYS` пуст, сервис при старте создаёт случайный ключ и печатает строку `DL_API_KEY=<ключ>`.
- Вместо ключа маршруты анализа принимают токен кабинета: `Authorization: Bearer <токен>` (см. ниже).

### Личный кабинет

База — SQLite в `DL_DATA_DIR`; значения анализов, ответы и референсы в ней зашифрованы (Fernet). Переменные:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `DL_DATA_DIR` | `data/app` в репозитории; в Docker — `/data` (том `jm-data`) | каталог базы кабинета |
| `DL_DATA_KEY` | пусто — ключ создаётся файлом `<DL_DATA_DIR>/key` (только демо) | ключ шифрования Fernet; несколько через запятую — смена ключа |
| `DL_DATA_KEY_FILE` | пусто | путь к файлу с ключом (секрет Docker): права не шире `0600`, файл — не в томе с базой; вместе с `DL_DATA_KEY` не задаётся |
| `DL_DATA_MAX_MB` | `512` | предел размера базы кабинета; дальше новые записи и регистрации — `507 storage_full` (вход, чтение, выгрузка и удаление работают) |
| `DL_MAX_SIGNUPS_PER_DAY` | `1000` | регистраций за сутки на весь сервис; дальше — `503 signups_paused` |
| `DL_SIGNUP_IP_PER_HOUR` | `30` | регистраций в час с одного адреса (IPv6 — с сети `/64`); дальше — `429`. На общем Wi-Fi площадки или за NAT клиники все гости делят один адрес — для демо с залом ставьте больше |
| `DL_COOKIE_SECURE` | `0` | `1` — сайт за HTTPS: cookie сессии `__Host-jm_session` с флагом `Secure` и заголовок `Strict-Transport-Security` (HSTS, год); включайте всегда, когда сайт открыт по HTTPS |
| `DL_CORS_ORIGINS` | пусто | сайты через запятую, которым разрешены запросы к `/api/v1/*` из браузера (без cookie) |
| `DL_TRUSTED_PROXIES` | пусто — никому | адреса и сети обратных прокси через запятую (`127.0.0.1`, `172.16.0.0/12`): только от них принимаются `X-Forwarded-For` / `-Proto` / `-Host` (адрес клиента для лимитов, схема и хост для проверки `Origin`) |

Ключ: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
**Вне демо ключ обязателен и хранится не в томе с базой** (`DL_DATA_KEY` из хранилища секретов или
`DL_DATA_KEY_FILE`): ключ-файл рядом с базой защищает только от утечки самого файла базы.
Стереть базу в Docker целиком: `docker compose down -v`.

Токен из ответа на вход («Вход») живёт 7 дней, вместе с cookie сайта; для интеграции создайте именованный токен
на 30 дней (`POST /api/v1/me/tokens`). По Bearer-токену новый токен, ссылку врачу и «выйти везде»
(`POST /api/v1/me/logout-all`) — только с паролем в поле `password`; смена пароля — `POST /api/v1/me/password`
(`{"old","new"}`, отзывает остальные сессии и токены).

```bash
# регистрация пациента → токен; запись анализа; история; удаление аккаунта
TOKEN=$(curl -s http://127.0.0.1:8080/api/v1/auth/register -H "Content-Type: application/json" \
  -d '{"login":"demo_patient","password":"demo-pass-1","role":"patient","consent":true}' | jq -r .token)
curl -s http://127.0.0.1:8080/api/v1/me/records -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"date":"2026-09-01","input":{"sex":"F","age_years":34,"values":{"hemoglobin":118,"ferritin":11}}}'
curl -s http://127.0.0.1:8080/api/v1/me/history -H "Authorization: Bearer $TOKEN"
curl -s -X DELETE http://127.0.0.1:8080/api/v1/me -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"password":"demo-pass-1"}'
```

Тела запросов кабинета — только JSON с `Content-Type: application/json` (иначе 415). Код 201 — у регистрации и новой
записи анализа, остальные успешные ответы — 200; вход с неверным паролем — 401 `invalid_credentials`, занятый логин —
409 `login_taken`. Страница сайта ходит в те же маршруты
с cookie `jm_session` и заголовком `X-Justmedit: 1` (защита от подделки запроса). Все маршруты и форматы —
`docs/CONTRACTS.md`, раздел «Хранение и кабинет»; безопасность — `docs/security.md`, «Личный кабинет».

Остальные настройки: `DL_UI_RATE_PER_MIN` (30; в `docker-compose.yml` — 120: расчётов страницы демо в минуту с адреса,
справочник страницы в лимит не входит), `DL_MAX_UPLOAD_MB` (10), `DL_MAX_BATCH` (10000), `DL_HOST`, `DL_PORT` (8080).
Только для `docker compose`: `DL_PUBLISH` (`127.0.0.1:8080`), `DL_CLINIC_PUBLISH` (`127.0.0.1:8081`),
`DL_CLINIC_API_KEY` (ключ мини-сайта; по умолчанию `dl-demo-key`).

### Публикация по ссылке

Публичная ссылка на демо — только на сервере команды. Перед выкладкой:

1. Свой ключ API в `DL_API_KEYS`, не демонстрационный `dl-demo-key`.
2. Лимит запросов включён: `DL_UI_RATE_PER_MIN` — расчётов страницы демо (`POST /ui/*`) в минуту с адреса (в коде
   по умолчанию 30, в `docker-compose.yml` — 120: на общем Wi-Fi все гости делят адрес; справочник страницы
   `GET /ui/reference`, `/ui/examples` отдаётся без лимита, с кешем на 5 минут). Он работает всегда. За прокси
   задайте его адрес или сеть в `DL_TRUSTED_PROXIES` — иначе все клиенты делят адрес прокси (`X-Forwarded-For`
   от остальных не учитывается); лимит по адресу клиента полезно поставить и на прокси.
3. На странице есть строка «Не вводите персональные данные» — она в шапке каждой страницы.
4. Сервис наружу не ходит: исходящих запросов, CDN и внешних шрифтов нет. Страница по кнопке «Выбрать на карте»
   грузит только картинки подложки с tile.openstreetmap.org (ADR 0008); геолокация работает по HTTPS.
5. Порт публикуется через `DL_PUBLISH`; TLS включается на обратном прокси сервера команды, сам сервис работает
   по HTTP. За HTTPS — `DL_COOKIE_SECURE=1`.
6. Кабинет: ключ шифрования — `DL_DATA_KEY` или `DL_DATA_KEY_FILE` (не демо-ключ в томе с базой).

```bash
# на сервере команды, рабочий каталог — корень репозитория
DL_API_KEYS='<свой ключ>' DL_PUBLISH=127.0.0.1:8080 DL_COOKIE_SECURE=1 DL_TRUSTED_PROXIES=172.16.0.0/12 \
  DL_DATA_KEY='<ключ Fernet>' docker compose up -d --build
```

Подробно, с проверкой после выкладки, — `docs/security.md`, раздел «Публикация по ссылке».

### Как открыть демо и что нажать

1. Откройте <http://127.0.0.1:8080/>.
2. Нажмите пример 1 «Гемоглобин в норме, а запас железа?». Анемии нет, но риск скрытого дефицита железа
   по скринингу повышен; первым предложен ферритин. Ниже — «Где сдать рядом»: «Определить моё положение»
   или «Выбрать на карте» покажут 5 ближайших пунктов; кнопки DOCX и PDF над отчётом скачивают открытую вкладку.
3. Нажмите «Добавить ферритин 9 мкг/л». Появится сигнал по порогу ВОЗ. Откройте вкладку «Пациенту».
4. Нажмите примеры 2–8: по одному на каждый трудный случай, тяжёлую анемию и беременность.
5. Откройте «Проверить на своём файле» и загрузите CSV или XLSX — в схеме кейса или со своими названиями столбцов:
   на шаге «Столбцы» проверьте сопоставление и единицы, предупреждения покажут, чего не хватает. Бланк одного анализа
   (фото, PDF с текстом или скан — OCR в Docker-версии, TXT, CSV / XLSX) загружается на главной кнопками
   «Сфотографировать бланк», «Загрузить PDF» или в блоке «Загрузить файл или вставить текст»: значения попадают
   в форму для сверки.
6. Внизу главной страницы раскройте свёрнутый блок «Для проверяющих: проверка API»: запрос без ключа (отказ)
   и с ключом (ответ).
7. Откройте «API» (`/developers`): в консоли маршрут `POST /api/v1/analyze`, авторизация X-API-Key, ключ `dl-demo-key`,
   «Отправить» — код, время, заголовки и ответ. Ниже — тот же запрос на curl, JavaScript и Python.

Сценарий показа на 2,5 минуты — `docs/demo_script.md`.

### Командная строка

Запуск из исходников, рабочий каталог — корень репозитория: `uv run deficitlens …` (после `uv sync`) или
`PYTHONPATH=src python3 -m deficitlens_core.cli …`. В Docker та же программа — `docker compose run --rm cli <команда>`
(файлы — в `./data/in` и `./data/out`). `--mapping` — файл YAML с поправками к `config/class_mapping.yaml` и словарём `columns` «столбец файла → код показателя».

| Команда | Что делает |
|---|---|
| `deficitlens analyze [--in файл.json]` | один анализ из JSON (по умолчанию из стандартного ввода) → полный ответ |
| `deficitlens predict --in файл.csv --out pred.csv [--mode auto\|clinical\|benchmark] [--summary s.json] [--mapping m.yaml]` | пакетная расшифровка файла в схеме кейса |
| `deficitlens train [--what all\|case\|screen] [--case путь] [--nhanes путь] [--out каталог]` | обучить модели |
| `deficitlens evaluate [--what all\|case\|screen] [--case путь] [--nhanes путь] [--out каталог]` | посчитать метрики в `docs/metrics/` |
| `deficitlens lab-reference --in cbc.csv --name имя [--dry-run]` | справочник ОАК своей лаборатории для скрининга |
| `deficitlens serve [--host 127.0.0.1] [--port 8080]` | запустить веб-сервис |

```bash
echo '{"sex":"F","age_years":34,"values":{"hemoglobin":124,"MCV":82,"RDW":15.2}}' \
  | PYTHONPATH=src python3 -m deficitlens_core.cli analyze
```

### Проверка после развёртывания

Рабочий каталог — корень репозитория:

```bash
docker compose run --rm verify        # то же, что verify.sh, внутри контейнера (зависимости уже в образе)
uv sync --extra dev                   # без Docker, один раз: зависимости сервиса и тестов
uv run python scripts/run_tests.py    # тесты без Docker (pytest не нужен)
uv run bash scripts/verify.sh         # тесты → модели → сервер на свободном порту → запросы → остановка
bash examples/curl.sh                 # запросы к уже запущенному сервису (ключ в DL_API_KEY)
```

`verify.sh` и `make verify`/`make test` берут интерпретатор из окружения проекта `.venv` (его создаёт
`uv sync --extra dev`), если оно есть, иначе `python3` из `PATH`; другой — переменной `PYTHON=/путь/к/python`
(для `make` — `PY=`). Если у выбранного Python нет зависимостей сервиса, `verify.sh` сразу пишет одну строку
«установите зависимости: uv sync --extra dev» вместо сотни упавших тестов. Причины SKIP печатаются те, что назвали
сами тесты (нет файла кейса, файла NHANES, программы tesseract), с числом тестов на каждую.

Без Docker тестам нужна группа зависимостей `dev` (`uv sync --extra dev`): в ней пакет httpx2 (клиент тестов Starlette), без которого
тесты API (170 тестов в `tests/api`) падают при импорте `starlette.testclient`. Остальные тесты работают и без неё.

`verify.sh` печатает таблицу PASS / FAIL / SKIP. Сам `docker compose` он не запускает.

## Входные и выходные данные, API

**Вход одного анализа** — JSON: пол, возраст в годах (от 18), значения показателей. Гемоглобин обязателен.
Персональные данные не нужны, полей для них нет.

```json
{"sex": "F", "age_years": 34, "values": {"hemoglobin": 124, "MCV": 82, "RDW": 15.2, "ferritin": {"value": 9, "unit": "ng/mL"}}}
```

Число без единицы считается записанным в основной единице показателя (гемоглобин — г/л, ферритин — мкг/л).
Коды показателей совпадают с именами столбцов файла кейса. Список кодов и единиц — `config/analytes.yaml`
или `GET /api/v1/reference`.

**Выход** — JSON с разделами: `level1`, `level2`, `hidden_deficiency`, `flags`, `checklist`, `next_tests`,
`explanation`, `values`, `reports` (врачу и пациенту), `normalization`, `limitations`, `version`.
Схемы — `src/deficitlens_core/schemas.py`.

**Вход из файла** — CSV или XLSX: строка на пациента, столбцы `sex`, `age_years` и коды показателей.
**Выход** — CSV со столбцами `patient_id`, `anemia`, `case_group`, `anemia_class`, `deficiency_cause`,
`confidence`, `hidden_deficiency`, `mode`, `status`, `reject_reason` и сводка. Если в файле есть метки, считаются метрики.

**Маршруты** (порт 8080):

| Маршрут | Ключ | Что делает |
|---|---|---|
| `GET /healthz` | нет | состояние и версии |
| `POST /api/v1/analyze` | да | один анализ → полный ответ |
| `POST /api/v1/batch` | да | до 10 000 записей → сводка и результат по каждой |
| `POST /api/v1/columns` | да | файл → что сервис понял в каждом столбце, догадки для своих названий, проверка «хватает ли данных» |
| `POST /api/v1/benchmark` | да | файл (схема кейса или своя структура с полем `mapping`) → предсказания и сводка; с `?format=csv` — файл CSV |
| `POST /api/v1/parse` | да | бланк одного анализа → значения для сверки: JSON `{"text": "…"}` или файл в поле `file` (фото JPEG / PNG / WEBP, PDF с текстом или скан — OCR в Docker-версии, TXT, CSV / XLSX) |
| `GET /api/v1/reference` | да | показатели, пороги с источниками, цены, версии |
| `GET /api/v1/openapi.json` | нет | описание API (OpenAPI 3.0, написано вручную): все маршруты, схемы, примеры |
| `/api/v1/auth/*`, `/api/v1/me/*`, `/api/v1/shares/accept`, `/api/v1/doctor/*` | вход: Bearer-токен или cookie сайта | личный кабинет пациента и врача: вход, история анализов, доступ врачу (ADR 0009); список — в `openapi.json`, формы ответов — `docs/CONTRACTS.md` |
| `GET /`, `GET /benchmark`, `GET /developers` | нет | страницы демо; `/developers` — API для встраивания |
| `/ui/*` | нет, лимит запросов на адрес | то же, что `/api/v1/*`, для страницы демо |
| `GET /login`, `GET /cabinet`, `GET /share` | нет | страницы кабинета |

Ошибка ввода — 422 с телом `{"error": {"code", "message", "field"}}`. Большой запрос — 413. Лимит — 429.
Тяжёлых расчётов (batch, benchmark, columns, parse; в кабинете — история `me/history` и история пациента у врача,
загрузка `me/import`) не больше двух одновременно на процесс, иначе — 503 с `Retry-After`.

```bash
curl -X POST http://127.0.0.1:8080/api/v1/analyze \
  -H "X-API-Key: $DL_API_KEY" -H "Content-Type: application/json" \
  -d '{"sex": "F", "age_years": 34, "values": {"hemoglobin": 124, "MCV": 82, "RDW": 15.2}}'
```

**Авторизация.** Маршруты анализа (`analyze`, `batch`, `columns`, `benchmark`, `parse`, `reference`) принимают
ключ `X-API-Key` или токен пользователя `Authorization: Bearer <токен>`. Ключ — только для запросов с сервера:
в коде страницы его увидит любой посетитель. В браузере и на чужом сайте — токен пользователя (`POST /api/v1/auth/login`),
а домен сайта добавляется в `DL_CORS_ORIGINS`.

**Страница для разработчиков** — <http://127.0.0.1:8080/developers> (пункт «API» в шапке): консоль запросов
(маршрут, авторизация, тело-пример, ответ с кодом, временем и заголовками), примеры curl / JavaScript fetch /
Python requests по состоянию консоли, справочник маршрутов по группам, готовая форма расшифровки для своего сайта,
сценарий кабинета через API, коды ошибок и лимиты. Машиночитаемое описание — `GET /api/v1/openapi.json`
(ключ не нужен; подходит для Swagger UI, Postman и генераторов клиентов). Тест `tests/api/test_openapi.py`
сверяет его с маршрутами `app.py` и с контрактом `docs/CONTRACTS.md`.

Подробно — `docs/integration.md`. Готовые примеры — `examples/` (`curl.sh`, клиент на Python, пакет из выгрузки ЛИС,
мини-сайт клиники `clinic_site/`); запуск — `examples/README.md`.

## Метрики

Все числа — из `docs/metrics/case_metrics.json` и `docs/metrics/screen_metrics.json`. Полные таблицы, интервалы,
калибровка и слабые места — в `docs/model_card.md`. Числа для слайдов, у каждого источник, —
`docs/pitch/numbers.json` (выжимка — `docs/pitch/NUMBERS.md`); рисунки — `docs/pitch/figures/`, PNG и SVG
(создаёт `make figures`, то есть `scripts/make_figures.py`).

**Уровень 1.** Правило ВОЗ совпало с меткой `anemia` в 840 строках из 840 учебного набора кейса.

**Уровень 2**, учебный набор кейса (840 строк), кросс-валидация 5 фолдов × 3 повтора, среднее ± разброс по фолдам:

| Что | Клинический режим | Режим бенчмарка | Простой бустинг (для сравнения) |
|---|---|---|---|
| Точность, 12 классов, строка как есть | 0,849 ± 0,025 | 0,919 ± 0,020 | 0,881 ± 0,027 |
| Точность, 12 классов, только ОАК + железо + СРБ | 0,665 ± 0,032 | 0,638 ± 0,031 | 0,571 ± 0,031 |
| Точность, 12 классов, только ОАК | 0,573 ± 0,027 | 0,504 ± 0,035 | 0,411 ± 0,035 |
| Точность, 5 групп, строка как есть | 0,914 ± 0,020 | 0,952 ± 0,017 | 0,936 ± 0,015 |
| Точность, 5 групп, только строки с анемией | 0,864 ± 0,031 | 0,924 ± 0,027 | — |

Как это читать. Режим бенчмарка и простой бустинг пользуются подсказкой: в наборе кейса то, какие анализы
назначены, связано с классом. Клинический режим подсказку не использует, поэтому на полной строке он ниже,
а на неполной панели — выше и лучше откалиброван. Это точность на учебном наборе, а не клиническая точность.

**Скрининг скрытого дефицита железа** (`screen-v1`), NHANES, обучение на циклах 1999–2016, тест на 2017–2023,
женщины 18–49 лет с нормальным гемоглобином (2 180 человек в тесте):

| Что | Ферритин < 15 мкг/л | Ферритин < 30 мкг/л |
|---|---|---|
| AUC (95 % ДИ) | 0,822 (0,797–0,855) | 0,727 (0,707–0,749) |
| Направили 30 % (точка по умолчанию) → найдено случаев | 77 % | — |
| Доля подтверждённых направлений при 30 % | 18,5 % | — |
| Простое правило по индексам при 14,8 % направлений → найдено | 51 % | 28 % |
| Модель при тех же 14,8 % → найдено | 58 % | 33 % |

Всего скрининг проверен на 5 728 людях с нормальным гемоглобином (тест); главная цифра — по женщинам 18–49 лет.
У мужчин и у женщин 50+ случаев в тесте мало (13 и 17 для порога 15); преимущество модели перед простым правилом
там не показано. Точка направления на ферритин — 30 %;
врач может выбрать 20 или 40 % (`config/screen_thresholds.yaml`, `refer_share`). Модель завышает риск для порога 15 примерно на четверть (предсказано 0,098, наблюдается 0,077).
Данные — США; на российских данных проверки не было.

**Скорость** (`docs/perf.md`, 2 ядра): один анализ — p50 около 20 мс, p95 около 26 мс; файл на 10 000 строк —
0,7–2,6 с в зависимости от режима.

## Ограничения и особенности медицинской тематики

- **Не медицинское изделие.** Прототип не зарегистрирован и для решений о пациентах не применяется.
  Он не ставит диагноз и не назначает лечение.
- **Учебный набор кейса.** По нашим наблюдениям он похож на сконструированный: метка анемии совпадает
  с правилом ВОЗ в 840 строках из 840, а набор назначенных анализов подсказывает класс. Точность на нём
  не равна клинической. На других пациентах модель уровня 2 не проверялась.
- **Скрининг проверен на данных США.** Для российской лаборатории нужна проверка на её выгрузке с ферритином.
  У мужчин и женщин 50+ преимущество перед простым правилом не показано.
- **Причина по одному общему анализу крови не определяется** (точность по 12 классам 0,573). Дефицит B6
  и меди без их анализа не находится.
- **Пороги — черновик.** Каждый порог в `config/norms_ru.yaml` имеет источник, но тексты и пороги
  не утверждены врачом. Статусы — в `docs/norms.md`. Рабочие решения капитана по вопросам врачу
  (`docs/review/medic_decisions.md`) врач команды подтверждает или правит до предпитчинга.
- **Референсы проекта по умолчанию.** «Норма» показателей — сводная таблица команды от 04.10.2026
  (`docs/facts/reference_table.md`; решение капитана, `docs/review/medic_decisions.md`, п. 10; ЛДГ, непрямой
  билирубин, гаптоглобин, ретикулоциты, церулоплазмин — по ответам врача команды, п. 11; ожидает подтверждения
  врачом): `config/norms_ru.yaml → reference_ranges`, по полу, с первоисточником и статусом
  «нужен врач». Референс даёт статусы таблицы значений («в пределах / ниже / выше референса») и чек-лист.
  Гемолиз — по сочетанию признаков (п. 11): при анемии минимум два из четырёх (ЛДГ выше, непрямой билирубин выше,
  гаптоглобин ниже, ретикулоциты выше) — «подозрение», низкий гаптоглобин и ещё один — «сильное подозрение»;
  без анемии — «есть признаки, требующие проверки». Церулоплазмин значим только вместе со сниженной медью. Диагностические пороги (ВОЗ по Hb, ВОЗ 2020 по ферритину, КР) он не меняет.
  При беременности референсы проекта не применяются.
- **Локальные референсы лаборатории.** Набор `local_references.<имя>` в конфигурации (выбирается полем
  `lab_reference`) или поле запроса `reference_ranges` заменяют референсы по умолчанию; тогда врачу и в ответе API
  (`references.warning`) — «Использованы референсные интервалы лаборатории. Они имеют приоритет над значениями
  по умолчанию проекта; проверьте единицы, метод и возрастно-половую группу.» На странице — блок «Референсы
  лаборатории» в «Настройках для врача»: по каждому показателю видно значение по умолчанию для выбранного пола,
  свои нижняя/верхняя границы вписываются в единицах формы и уходят в запрос как `reference_ranges` (браузер их
  не сохраняет). Нормы с бланка (PDF, фото) попадают в эти поля галочкой «Применить референсы лаборатории
  с бланка»; набор референсов врача из кабинета подставляется в его расчёты. Жёсткие рамки ввода (`config/analytes.yaml → hard`)
  редактируются только в конфигурации.
- **B12 по NICE NG239.** Общий B12, активный B12 и гомоцистеин оцениваются числом по NICE NG239 с подписью
  «зарубежный источник; в КР РФ числового порога нет» (`policy.foreign_allowed`; глобально зарубежные пороги
  по-прежнему выключены, `use_foreign: false`). Серая зона общего B12 180–350 пг/мл — флаг «B12 требует
  функционального подтверждения» и досдать активный B12 и гомоцистеин. ММК — без диагностического порога
  (обычно < 0,30 мкмоль/л, зависит от метода). Доз и схем лечения сервис не приводит: «лечение — по клиническим
  рекомендациям Минздрава».
- **Только взрослые.** Возраст младше 18 лет отклоняется. При беременности работает только уровень 1:
  ферритин, модели, флаги и чек-лист не оцениваются. Для людей старше 65 лет пороги ВОЗ применяются по аналогии.
- **Пациенту** не выводятся диагнозы, лекарства, дозы и добавки.
- **Персональные данные.** Без входа ничего не хранится; в кабинете — SQLite, значения зашифрованы (Fernet),
  журнал доступа врачей; в журнал запросов значения анализов не пишутся. TLS — на обратном прокси. Это прототип,
  не система по 152-ФЗ: реальные данные пациентов не вводить.
- **Цены** (`config/prices.yaml`) — медиана по лабораториям Москвы на 03.10.2026, без взятия крови. В текстах
  отчётов их нет; на странице и в выгрузке — «средняя цена в регионе» в блоке «Где сдать рядом» (для области —
  цены Москвы с оговоркой, для других регионов — «цен нет»). Используются и в расчёте прироста информации.
- **Где сдать рядом** — только Москва и область и только пункты, размеченные в OpenStreetMap (у большинства нет
  адреса); расстояние по прямой. Подложка карты требует интернета у пользователя.

Подробно — `docs/limitations.md`, `docs/model_card.md`, `docs/security.md`.
